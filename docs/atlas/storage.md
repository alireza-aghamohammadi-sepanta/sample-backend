# Cloud Storage Service

The storage service in `app/services/storage.py` wraps the Google Cloud Storage SDK (`google-cloud-storage`). It handles path formulation, pre-signed upload URL generation, user object isolation, and blob existence validation for [asset management](assets.md).

## Architecture & Lifespan Integration

`StorageService` is decoupled from global configuration:
- Constructed with `bucket_name: str` and a `client: google.cloud.storage.Client`.
- An instance is constructed once during FastAPI startup in `main.py` and saved to `app.state.storage_service`.
- In local or test environments without GCP credentials or configured bucket names, `build_storage_service()` fails gracefully, allowing the rest of the application to boot normally (see [architecture](architecture.md)).
- Endpoints requiring storage use the `get_storage_service` dependency:
  ```python
  def get_storage_service(request: Request) -> StorageService:
      service = getattr(request.app.state, "storage_service", None)
      if service is None:
          raise HTTPException(
              status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
              detail="Cloud Storage is not available",
          )
      return service
  ```

## Object Path Conventions

Objects are organized under a strict 4-segment hierarchy:
```
users/{user_id}/{media_type}/{uuid}.{extension}
```
- **`user_id`**: Scopes all uploaded objects to their respective owner.
- **`media_type`**: Subdirectory reflecting the media type (`image` or `video`).
- **`uuid`**: A random `uuid.uuid4()` preventing collisions and enumeration.
- **`extension`**: The normalized file extension (e.g. `png`, `jpg`, `mp4`).

### Ownership Verification
`StorageService.get_owned_media_type(gcs_path, user_id)` verifies that an incoming object path adheres strictly to this structure:
1. Splits path into segments and asserts segment count is exactly 4.
2. Checks that prefix is `users`.
3. Validates that the embedded user ID string matches the caller's UUID.
4. Checks that the media type matches known enum values.
If any condition fails, it returns `None`, rejecting directory traversals or cross-tenant key forging before the bucket or database is touched.

## V4 Signed URLs

Clients upload files directly to Cloud Storage via HTTP `PUT` using V4 signed URLs generated by `generate_signed_url()`:

```python
def generate_signed_url(
    self,
    gcs_path: str,
    content_type: str | None = None,
    expiration: timedelta = SIGNED_URL_EXPIRATION,
) -> str:
    return self._blob(gcs_path).generate_signed_url(
        version="v4",
        method="PUT",
        expiration=expiration,
        content_type=content_type,
        headers={"x-goog-content-length-range": f"0,{MAX_UPLOAD_BYTES}"},
    )
```

### Upload Size Enforcement
The signed URL includes the extension header `x-goog-content-length-range: 0,524288000` (500 MB limit). Because this header is bound into the cryptographic V4 signature, Cloud Storage rejects uploads exceeding 500 MB at the edge, and the client cannot modify the limit without invalidating the signature.

## Blob Operations
- **`file_exists(gcs_path: str) -> bool`**: Invokes `blob.exists()` to verify physical presence in the bucket.
- **`public_url(gcs_path: str) -> str`**: Returns the public CDN/HTTPS address `https://storage.googleapis.com/{bucket}/{path}`.
